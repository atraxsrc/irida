# Irida app implementation plan (plan 3 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Irida becomes a native COSMIC app: `irida` with no arguments opens a
libcosmic window where a user picks, drafts (also from a wallpaper), edits,
compares, saves and applies a palette, tries it live, and undoes it; plus
`irida draft`, the remaining core gaps, and a .deb.

**Architecture:** Core first, app second. Tasks 1 to 8 add what the app needs
to `irida-core` (validation, store operations, versions and snapshots, target
status, live sessions, wallpaper drafts, the COSMIC wallpaper reader) and the
`irida draft` command, all tested without a display. Tasks 9 to 14 build the
app in `irida/src/app/` as a thin libcosmic layer over a pure state machine
(`state.rs`: `State`, `Msg`, `Effect`, `update`) and a synchronous effect
runner (`effects.rs`: `perform`), both tested without a display. Task 15
packages it. Task 16, try it live, is last: the spec names it the first thing
to slip, and nothing else depends on it.

**Tech Stack:** Rust 2024 (1.93+), libcosmic at rev
`e1f2cd2e52226aa50d59bb2cd6d43ffe290106ed` (the same rev as the existing
`cosmic-theme`/`cosmic-config` deps), tokio 1, `image` 0.25 (jpeg, png, webp),
cargo-deb.

**Spec:** `docs/superpowers/specs/2026-10-16-irida-design.md`, amended on this
branch with "Drafting from a wallpaper", "New from wallpaper" and `irida
draft`. Plans 1 and 2 are implemented (`feat/irida-core`, `feat/irida-plan2`).
The reference implementation of the wallpaper draft is
`docs/superpowers/specs/2026-10-16-wallpaper-draft.js`; its outputs for five
synthetic images are in `irida-core/tests/fixtures/draft/vectors.json` (each
case is 1000 RGBA pixels, a 40 by 25 image, base64).

## Global Constraints

- Everything in plans 1 and 2's Global Constraints still holds: edition 2024, pinned libcosmic rev for every cosmic crate, `round_ties_even` mix, uppercase `#RRGGBB`, explicit `git add` paths, tests never touch anything outside their temporary folders and never signal a process they did not start.
- No em-dashes or en-dashes anywhere (code, comments, docs, UI strings, commit messages).
- No email address, personal name, token or key in any committed file, the plan included. This covers `Cargo.toml` package metadata, the Debian changelog, the AppStream file and scripts (Task 15 takes the maintainer from the environment at build time).
- App ID: `io.github.atraxsrc.Irida` (libcosmic `APP_ID`, `.desktop` basename, icon name, metainfo id).
- Palette names match `^[A-Za-z0-9]+( [A-Za-z0-9]+)*$`; slugs match `^[a-z]+$`.
- `irida-core` stays GUI-free: no libcosmic widget crate in `irida-core/Cargo.toml` (it keeps `cosmic-theme` and `cosmic-config`).
- `irida/Cargo.toml` gains `libcosmic = { git = "https://github.com/pop-os/libcosmic", rev = "e1f2cd2e52226aa50d59bb2cd6d43ffe290106ed", default-features = false, features = ["winit", "wayland", "tokio", "xdg-portal", "dbus-config", "about"] }` and `tokio = { version = "1", features = ["rt", "time"] }` (libcosmic does not re-export tokio). Leave out `a11y` (cosmic-term notes it crashes the file chooser).
- Every app behaviour that has logic is decided in `irida/src/app/state.rs` (`update`) or `irida/src/app/effects.rs` (`perform`) and unit-tested there; view functions only read `State` and emit `Msg`. The views are checked by hand (spec section 10).
- App code never calls `Ctx::for_app`, `Ctx::from_env` or `Dirs::from_env` except in `app::run`. Every app test uses `Ctx { dirs: Dirs::under(tmp.path()), path: vec![] }`, so no real binary is detected and nothing is signalled. No test sets an environment variable of its own process.
- UI copy is short and plain, in the user's terms ("Save", "Saved version 3", "Apply", "Applied to 6 apps"). Errors say what went wrong and what to do.
- Messages carried by libcosmic must be `Clone`: wrap non-`Clone` errors as `String` at the boundary.
- Adding a field or changing a signature updates every caller and literal in the same task (the reviewers check this): `ApplyRequest` (core tests, `irida/src/main.rs`), `KeyFileWrite` (`native/cosmic_term.rs`, `native/cosmic_desktop.rs`), `Pins::set` (`import.rs`, `tests/derive.rs`, `tests/export_docs.rs`, any other test).

**Environment (cloud session).** Install build deps first: `apt-get install -y
pkg-config libxkbcommon-dev libexpat1-dev libfontconfig-dev libfreetype-dev
cmake desktop-file-utils appstream lintian`, then `cargo install cargo-deb
--locked`. Building libcosmic needs network access to crates.io and github.com.
The first libcosmic build is slow; run `cargo build -p irida` once at the start
of Task 9. Tasks 7, 8 and 9 add dependencies, so `Cargo.lock` changes; that is
expected, and those tasks include `Cargo.lock` in their `git add`.

## Review Focus

1. **An edit that would make the palette file unreadable** (a name with a dash, `none` pinned on a slot other than `background`). Saving must refuse with the reason, and nothing on disk changes. Tests in Tasks 1 and 9.
2. **A live session interrupted by a crash, or one that switched mode midway.** The next start must offer Revert, and Revert must give back the files from before the session byte for byte, even after many edits. Tests in Tasks 6 and 16.
3. **A palette file that cannot be parsed** in the store. The app shows it read-only with the error and its text and never writes it. Tests in Tasks 2 and 9.
4. **A wallpaper source that is not an image file** (a colour or gradient source, a missing file, an unparsable key). The wallpaper draft falls back to the file chooser with a plain message, never crashes. A slideshow folder gives its first image by name, and COSMIC's default file with `#true` is read after replacing `#true`/`#false`. Tests in Tasks 8 and 13.
5. **The app launched from the dock with a short `PATH`.** Target detection must still find `/usr/bin` apps. Test in Task 5.

### Task 6: Live sessions

**Files:**
- Create: `irida-core/src/live.rs`
- Modify: `irida-core/src/record.rs`, `irida-core/src/apply.rs`, `irida-core/src/lib.rs`
- Test: `irida-core/tests/live.rs`

**Interfaces:**
- Consumes: Task 4's `NativeUndo` entries, Task 5's `live_only`.
- Produces:
  - `record.rs`: `pub fn load(dirs: &Dirs, id: u32) -> io::Result<Record>`; `RecordWriter::reopen(dirs: &Dirs, id: u32) -> io::Result<RecordWriter>` (reloads `record.toml` and the blob count); `RecordWriter::has(&self, path: &Path) -> bool`; a non-consuming `RecordWriter::save(&mut self) -> io::Result<()>` that rewrites `record.toml` through a temporary file it removes first. `record::latest` skips the record named by the live marker.
  - `apply.rs`: `pub(crate) fn apply_into(ctx: &Ctx, settings: &Settings, req: &ApplyRequest, rec: &mut RecordWriter, session: bool) -> Result<ApplyReport, ApplyError>`. `apply()` calls it with a fresh writer and `session = false` (behaviour unchanged). With `session = true`: a path's blob is captured only the first time the session writes it; for a key file already captured, a later apply still adds a `TermScheme` entry for each new (mode, id) and a `TermProfileTheme` entry for each new (profile, field), with `before` taken from the session's captured blob of that key file, not the current file; `record.toml` is saved after each apply; a failed write restores only this call's writes from this call's in-memory pre-write bytes and never deletes the record; no prune.
  - `live.rs`: `pub struct LiveSession` (record id once created, palette slug). `LiveSession::start(ctx: &Ctx, palette_slug: &str) -> io::Result<LiveSession>` writes only the marker `$XDG_STATE_HOME/irida/live.toml` (`palette = "<slug>"`, and `record = <id>` once the record exists); the record folder is created on the first successful apply.
  - `LiveSession::apply(&mut self, ctx: &Ctx, settings: &Settings, req: &ApplyRequest) -> Result<ApplyReport, ApplyError>` forces `live_only` and calls `apply_into` with `session = true`.
  - `keep(self, ctx: &Ctx) -> io::Result<()>`: removes the marker, so the record becomes a normal apply record that `irida undo` undoes in one step, then prunes to 10.
  - `revert(self, ctx: &Ctx) -> Result<UndoReport, UndoError>`: restores the session record with `RestoreMode::Rollback` (the files from before the session, byte for byte), deletes it and the marker, then reloads every live target that is detected.
  - `pub fn pending(dirs: &Dirs) -> Option<LiveSession>`: the marker's session; a marker whose record id is set but missing is deleted and gives `None`; a marker with no record yet is deleted and gives `None` (nothing was written).
  - `record::prune` never deletes the record named by the marker. Core `undo` returns the new `UndoError::LiveSessionOpen` ("A live session is open; keep or revert it in Irida first") while a marker with a record exists; the CLI prints it and exits 2.
