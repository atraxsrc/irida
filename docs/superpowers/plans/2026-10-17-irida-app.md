# Irida app implementation plan (plan 3 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Irida becomes a native COSMIC app: `irida` with no arguments opens a
libcosmic window where a user picks, drafts (also from a wallpaper), edits,
compares, saves and applies a palette, tries it live, and undoes it; plus
`irida draft`, the remaining core gaps, and a .deb.

**Architecture:** Core first, app second. Tasks 1 to 8 add what the app needs
to `irida-core` (validation, store operations, versions and snapshots, target
status, live sessions, wallpaper drafts, the COSMIC wallpaper reader) and the
`irida draft` command, all tested without a display. Tasks 9 to 15 build the
app in `irida/src/app/` as a thin libcosmic layer over a pure state machine
(`state.rs`: `State`, `Msg`, `update` returning `Effect`s) whose tests run
without a display. Task 16 packages it.

**Tech Stack:** Rust 2024 (1.93+), libcosmic at rev
`e1f2cd2e52226aa50d59bb2cd6d43ffe290106ed` (the same rev as the existing
`cosmic-theme`/`cosmic-config` deps), `image` (jpeg, png, webp), cargo-deb.

**Spec:** `docs/superpowers/specs/2026-10-16-irida-design.md`, amended on this
branch with "Drafting from a wallpaper", "New from wallpaper" and `irida
draft`. Plans 1 and 2 are implemented (`feat/irida-core`, `feat/irida-plan2`).
The reference implementation of the wallpaper draft is
`docs/superpowers/specs/2026-10-16-wallpaper-draft.js`.

## Global Constraints

- Everything in plans 1 and 2's Global Constraints still holds: edition 2024, pinned libcosmic rev for every cosmic crate, `round_ties_even` mix, uppercase `#RRGGBB`, explicit `git add` paths, tests never touch anything outside their temporary folders and never signal a process they did not start.
- No em-dashes or en-dashes anywhere (code, comments, docs, UI strings, commit messages).
- No email address, personal name, token or key in any committed file. This includes `Cargo.toml` package metadata, the Debian changelog and the AppStream file (Task 16 supplies the maintainer only at build time).
- App ID: `io.github.atraxsrc.Irida` (libcosmic `APP_ID`, `.desktop` basename, icon name, metainfo id).
- Palette names match `^[A-Za-z0-9]+( [A-Za-z0-9]+)*$`; slugs match `^[a-z]+$`.
- `irida-core` stays GUI-free: no libcosmic widget crate in `irida-core/Cargo.toml` (it may keep `cosmic-theme` and `cosmic-config`).
- libcosmic features for `irida`: `default-features = false, features = ["winit", "wayland", "tokio", "xdg-portal", "dbus-config", "about"]`. Leave out `a11y` (cosmic-term notes it crashes the file chooser).
- Every app behaviour that has logic is decided in `irida/src/app/state.rs` and unit-tested there; view functions only read `State` and emit `Msg`. The views are checked by hand (spec section 10).
- UI copy is short and plain, in the user's terms ("Save", "Saved", "Apply", "Applied to 6 apps"). Errors say what went wrong and what to do.
- Messages carried by libcosmic must be `Clone`: wrap non-`Clone` errors as `String` at the boundary.

**Environment (cloud session).** Install build deps first: `apt-get install -y
pkg-config libxkbcommon-dev libexpat1-dev libfontconfig-dev libfreetype-dev
cmake` (plus `desktop-file-utils appstream lintian` for Task 16), and
`cargo install cargo-deb --locked`. Building libcosmic needs network access to
crates.io and github.com. The first libcosmic build is slow; run `cargo build -p
irida` once before Task 9's tests.

## Review Focus

1. **An edit that would make the palette file unreadable** (a name with a dash, `none` pinned on a slot other than `background`). Saving must refuse with the reason, and nothing on disk changes. Tests in Tasks 1 and 9.
2. **A live session interrupted by a crash or a killed process.** The next start must offer Revert, and Revert must restore the files from before the session even after many edits. Tests in Tasks 6 and 15.
3. **A palette file that cannot be parsed** in the store. The app shows it read-only with the error and never writes it. Tests in Tasks 2 and 9.
4. **A wallpaper that is not a single image file** (a slideshow folder, a colour or gradient source, a missing file, COSMIC's own default file with `#true` in it). The wallpaper draft must fall back to the file chooser with a plain message, never crash. Tests in Tasks 8 and 13.
5. **The app launched from the dock with a short `PATH`.** Target detection must still find `/usr/bin` apps. Test in Task 5.

### Task 8: Images, the current COSMIC wallpaper, `irida draft` and the no-display start

**Files:**
- Create: `irida-core/src/wallpaper.rs`

**Interfaces:**
- Produces:
  - `pub fn load_pixels(path: &Path) -> Result<Vec<u8>, WallpaperError>`: decode, scale to 160 px on the longest side (`image::imageops::FilterType::Triangle`), RGBA8 bytes. `WallpaperError::{NotImage(PathBuf), Io(PathBuf, String)}` with plain messages.
  - `pub fn name_from_file(path: &Path) -> String` (step 9; the reference `nameFromFile`).
  - `pub fn current_wallpaper(dirs: &Dirs) -> Option<PathBuf>`: reads `com.system76.CosmicBackground/v1` from `dirs.config/cosmic` and then `/usr/share/cosmic` (the system default key `all` ships with `#true`, so replace `#true`/`#false` with `true`/`false` before parsing with a local serde mirror). Order: when `same-on-all` is false and `backgrounds` names outputs, the first `output.<name>` entry; else `all`. A `Path` source that is a file is returned; a folder returns its first image file by name; a `Color` source, a missing file or any parse error returns `None`.
